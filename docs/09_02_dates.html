Dates & Time

As shown, for working with dates and times we are going to use lubridate package. It is now a part of tidyverse and is included when you load it, but in older R versions could not been included and you will need to load it individually.

library(tidyverse) # use library(lubridate) for this package only

We can see three data types…

  • Dates
  • Time
  • Datetime, combination of the first two identifying a time period. Take into account that in tibbles they are identified as datetime (dttm) but R base uses POSIXct as normal type.

We can get today`s date…

today()
[1] "2026-09-05"

Or current date time…

now()
[1] "2026-09-05 17:46:32 CEST"

Parsing dates

Normally we will receive this data as Strings, this will make us think use the parsing functions we learn at the first block of this unit, but…

lubridate has a more easy way of doing it with multiple purpose functions where we just need to specify the order with y, m or d

ymd("2022-05-04")
[1] "2022-05-04"
ymd("22-May-04")
[1] "2022-05-04"

More examples, the syntax offered by lubridate has a lot of possibilites to parse dates and times:

mdy("May 4th, 2022")
[1] "2022-05-04"
dmy("4 of May of 2022")
[1] "2022-05-04"
ymd_hms("2022-05-04 20:11:58")
[1] "2022-05-04 20:11:58 UTC"
mdy_hm("04/05/2022 00:01")
[1] "2022-04-05 00:01:00 UTC"

We can simply create date with individual variables using make_datetime().

flights %>% 
  select(year, month, day, hour, minute) %>% 
  mutate(departure = make_datetime(year, month, day, hour, minute)) %>%

Change formats

You can change between formats…

as_datetime(today())
[1] "2026-09-05 UTC"
as_date(now())
[1] "2026-09-05"

Extracting components

You can extract components for dates and time…

datetime <- ymd_hms("2022-05-04 12:34:56")
year(datetime)
[1] 2022
month(datetime)
[1] 5
mday(datetime) # day of month
[1] 4
yday(datetime) # day of year
[1] 124
wday(datetime) # day of week
[1] 4
hour(datetime)
[1] 12
minute(datetime)
[1] 34
second(datetime)
[1] 56

In these examples are extractions are numerical. So we have the day, hour etc. But for some date attributes (like day of week or month) we have a name. We change the behavior of the functions to obtain the label.

datetime <- ymd_hms("2022-05-04 12:34:56")
month(datetime, label = TRUE)
[1] May
12 Levels: Jan < Feb < Mar < Apr < May < Jun < Jul < Aug < Sep < ... < Dec
wday(datetime, label = TRUE, abbr = FALSE)
[1] Wednesday
7 Levels: Sunday < Monday < Tuesday < Wednesday < Thursday < ... < Saturday

You can change labels output language.

wday(datetime, label = TRUE, abbr = FALSE, locale = Sys.setlocale("LC_TIME", "es_ES"))
[1] miércoles
7 Levels: domingo < lunes < martes < miércoles < jueves < ... < sábado

Modifying components

We can modify the components using the same functions

datetime <- ymd_hms("2022-05-04 12:34:56")

year(datetime) <- 2023
datetime
[1] "2023-05-04 12:34:56 UTC"
month(datetime) <- 01
datetime
[1] "2023-01-04 12:34:56 UTC"
hour(datetime) <- hour(datetime) + 1
datetime
[1] "2023-01-04 13:34:56 UTC"

Computations with dates and time

For computing with dates we need…

  • Duration, exact number of seconds
  • Periods, other units like months and weeks.

Duration

When making the difference between two dates, will obtain a difftime object…

my_age <- today() - ymd("1998 Mar 4")
my_age
Time difference of 10412 days
class(my_age)
[1] "difftime"

This object will contain the information regarding time period in seconds, minutes, hours, days, etc… pretty ambiguous.

Alternative, we can work with duration (in seconds)

as.duration(my_age)
[1] "899596800s (~28.51 years)"

Other useful functions… in seconds

dseconds(15)
[1] "15s"
dminutes(10)
[1] "600s (~10 minutes)"
dhours(c(12, 24))
[1] "43200s (~12 hours)" "86400s (~1 days)"  
ddays(0:5)
[1] "0s"                "86400s (~1 days)"  "172800s (~2 days)"
[4] "259200s (~3 days)" "345600s (~4 days)" "432000s (~5 days)"
dweeks(3)
[1] "1814400s (~3 weeks)"
dyears(1)
[1] "31557600s (~1 years)"

Making computations in seconds…

dyears(1) + dweeks(12) + dhours(15)
[1] "38869200s (~1.23 years)"
2 + dweeks(12)
[1] "7257602s (~12 weeks)"
tomorrow <- today() + ddays(1)
last_year <- today() - dyears(1)

Periods

Last methods will help making computations using seconds as our base… but we have other functions more intuitive for just operating with the exact period…

seconds(15)
[1] "15S"
minutes(10)
[1] "10M 0S"
hours(c(12, 24))
[1] "12H 0M 0S" "24H 0M 0S"
days(7)
[1] "7d 0H 0M 0S"
months(1:6)
[1] "1m 0d 0H 0M 0S" "2m 0d 0H 0M 0S" "3m 0d 0H 0M 0S" "4m 0d 0H 0M 0S"
[5] "5m 0d 0H 0M 0S" "6m 0d 0H 0M 0S"
weeks(3)
[1] "21d 0H 0M 0S"
years(1)
[1] "1y 0m 0d 0H 0M 0S"

Computing…

ymd("2022-01-01") + years(1)
[1] "2023-01-01"
ymd("2022-01-01") + months(1)
[1] "2022-02-01"
ymd("2022-01-01") + days(1)
[1] "2022-01-02"

Take care when mixing both systems… or periods or duration not both…

ymd("2022-01-01") + dyears(1)
[1] "2023-01-01 06:00:00 UTC"
ymd("2022-01-01") + years(1)
[1] "2023-01-01"
